# 目标架构

> 本文讲**目标形态**：目录怎么放、配置怎么改、状态怎么判、哪些规则不能动。
> 只保留「使用者需要知道」的部分；内部设计与取舍理由不入库，见本地 `research/目标架构-设计笔记.md`。
>
> 现状流程见 [`流水线现状.md`](流水线现状.md)。

---

## 0. 一句话

> 说一次「做我的世界 2026-06 的合集三、合集四」，之后它自己找目录、自己跑。
> 该人动手时它告诉人；人做了什么，不需要回报给它。

---

## 1. 人的动作就是信号

系统里**没有审批门**，也不需要回报「我审过了」。

| 人工动作 | 耗时 | 系统怎么知道做完了 |
|---|---|---|
| 剪映里的创作剪辑 | 15 min | 不观测。素材达标即「剪辑中」 |
| 字幕审查 | 5 min | **不单独记** —— 由「导出启动」反证 |
| 成片抽检（可选） | 5 min | 不可观测，也不阻塞任何环节 → **不建模** |

**理由**：人不会没审字幕就花 45 分钟导出。所以「导出启动」这一个事实，本身就证明了「剪辑完成 + 字幕审完」。
反过来，如果建一张审批表，就得靠人回报；人一忘，数据就是假的 —— **假数据比没数据更坏**。

**原则：动作即意图；不为不可观测的事实建表。**

## 2. 目录约定（唯一真相）

```
<workspace.root>\
└── {游戏}-{批次}\                       # 例：我的世界-2026-06
    ├── game.yaml                        # 本批次**规则**（建完即定稿，人可手改）
    ├── 合集清单.yaml                     # **迟绑定事实**：草稿名、片头片尾映射（程序写）
    ├── 标题.md                          # 公共前缀 + 每合集一节（副标题 + 20 条标题）
    ├── 台账.xlsx                        # 批次级台账
    ├── 素材库\                          # 剪辑原料：打招呼语音、混剪片段。**程序不读**
    ├── 片头\  片尾\                     # 已合成的成品，按合集组命名
    ├── 术语库\                          # 该游戏的 ASR 易错词
    ├── log\                             # 运行日志 + events.jsonl
    └── 合集\
        └── 合集三\
            ├── 素材\                    # OBS 原始录屏
            ├── 剪辑\                    # 长片导出、.txt、.srt、corrected.txt
            └── 成片\                    # 20 个成片
```

### 2.1 目录语义

| 目录/文件 | 级别 | 放什么 | 谁写 | 谁读 |
|---|---|---|---|---|
| `game.yaml` | 批次 | **规则**：时长、命名、导出参数、主播、类别 | `init` 一次，人可手改 | 所有环节（只读） |
| `合集清单.yaml` | 批次 | **迟绑定事实**：草稿名、片头片尾映射 | 程序 | `export`、`splice` |
| `标题.md` | 批次 | 公共前缀 + 每合集副标题 + 每集标题 | `correct` / `plan` | `rename`、`ledger` |
| `素材库/` | 批次 | 剪辑用的原料堆 | 人 | **程序不读** |
| `片头/` `片尾/` | 批次 | 已合成的成品 | 人 | `splice` |
| `术语库/` | 批次 | ASR 易错词表 | 人 | `correct` |
| `合集/合集X/素材/` | 合集 | OBS 原始录屏 | 人 | `balance`、状态判定 |
| `合集/合集X/剪辑/` | 合集 | 长片、`.txt`、`.srt`、`corrected.txt` | 剪映 / 程序 | 程序 |
| `合集/合集X/成片/` | 合集 | 成片 | `splice` / `rename` | `ledger` |
| `台账.xlsx` | 批次 | 交付台账 | `ledger` | 人 / 对接方 |

### 2.2 `conf/` 放什么

```
conf/
├── 默认规则.yaml            # 全项目默认值（导出参数、时长、集数、命名模板）
├── 游戏规则/{游戏}.yaml      # 只写与默认不同的键，一般游戏没有
├── 知识库/{游戏}/*.md        # ASR 易错词表 / 专有名词，游戏级、跨批次复用、人可改
├── 本机.example.yaml        # 本机配置模板（入库）
├── 本机.yaml                # 本机路径与工具（人写，不入库）
├── 本机能力.example.yaml    # 能力档案模板（入库）
└── 本机能力.yaml            # 程序实测的编码器/速度/超时（程序写，不入库）
```

**为什么知识库进 `conf/` 而不进代码目录**：它是**游戏级资产** —— 跨批次复用的
ASR 易错词表，丢了要重新让模型生成一遍。换机器 clone 后必须还在，所以入库；
但它不是代码，所以不该躺在 `src/` 里。

**为什么批次产出的标题不在这里**：标题属于某个批次，写在工作区的 `{批次}/标题.md`。
仓库里不该有用户业务数据的第二份。

---

### 2.3 片头 = 合集组级别

片头不是"一个游戏一个"，也不是"一个合集一个"，而是**几个合集共用一套**（1-3 / 4-5 / 6-7-8 / 9-10）。

**程序只认一件事：`片头/` 下的成品文件路径。**

- `素材库/` = 原料，程序不读
- `片头/` = 成品，程序只读这个
- `合集清单.yaml` 的 `templates.intro_mapping` = 合集 → 成品文件，允许多个合集指向同一个

## 3. 配置：规则在批次里定死

### 3.1 三份文件，两次使用

| | 文件 | 作用 | 谁读 |
|---|---|---|---|
| **公共规则** | `conf/默认规则.yaml` | 全项目通用默认值 | **只有 `init` 读** |
| **游戏差异** | `conf/游戏规则/{游戏}.yaml` | **只写与默认不同的键**；一般游戏没有这个文件 | **只有 `init` 读** |
| **批次快照** | `{游戏}-{批次}/game.yaml` | 本批次的**完整**配置 | **运行时只读它** |

```
init:  默认规则 ─┐
                 ├─深合并→ 问答 ─→ game.yaml（完整快照）
       游戏差异 ─┘
run :                           game.yaml ◀── 唯一输入
```

**关键：合并不发生在运行时。** 运行时只有 `game.yaml` 一份，不存在「先读 A 再被 B 覆盖」。

**这条带来的直接好处：甲方改 `conf/默认规则.yaml`，只影响**新**批次；已建的批次行为不变，可复现。**

### 3.2 怎么改规则

| 想改什么 | 改哪里 | 影响范围 |
|---|---|---|
| 全项目默认值（导出参数、时长、集数、命名模板） | `conf/默认规则.yaml` | **新**批次 |
| 某个游戏的特殊值（如我的世界 2.5h/合集） | `conf/游戏规则/{游戏}.yaml` | **新**批次 |
| 某个已建批次的参数 | 该批次的 `game.yaml` | 仅该批次 |
| 分支业务（草稿名、片头映射） | 该批次的 `合集清单.yaml` | 仅该批次 |

> 具体字段和当前值直接看 `conf/` 下那三个文件，本文不复制一份（复制必漂移）。

### 3.3 `init` 就是「把问题问清楚」

```
📋 依据 conf/默认规则.yaml（+ 游戏差异）
1. 游戏？              我的世界
2. 批次？              2026-06（默认本月）
3. 建几个合集？        10
4. 每合集素材目标？    2h → 2.5h          ← 改
5. 每集正文时长？      6min → 7:30        ← 改
6. 每合集集数？        20
7. 导出参数？          1080P / 30fps / H.264 / mp4
8. 命名模板？          {主播}之{游戏} {副标题}
9. 片头片尾？          （可先空着 —— 拼接前才校验）
```

- 默认值全部来自公共规则；只改真正不同的那几项
- **非技术用户**：agent 把问题和默认值一起摆出来，回车即用
- **熟练用户**：`vedio init --game 我的世界 --batch 2026-06 --yes`

**片头片尾不要求建批次时就填。** 实际做法常是先把正片录完，片头片尾最后才做。
所以允许留空，只在 **`splice` 之前**校验；缺了就停下并明确反馈，不许自己编一个。

### 3.4 规则 vs 事实：两个文件，两种写入方

| | `game.yaml` | `合集清单.yaml` + `标题.md` |
|---|---|---|
| 性质 | **规则**（建批次时定） | **事实**（做完才知道） |
| 写入方 | 只有 `init`，人也可手改 | 程序边跑边追加 |
| 注释 | 大量，且必须保住 | 不需要 |

**为什么必须分开**：PyYAML 往返读写会抹掉注释。`game.yaml` 的注释是给人手改时看的，被程序重写一次就没了。**所以规则文件永不程序化重写。**

> ⚠️ `合集清单.yaml` 由程序维护，**人只核对不手改** —— 手改会被下一次登记覆盖。

## 4. 状态判定（全部读文件系统）

| 状态 | 判定条件 |
|---|---|
| **素材** | `素材/` 下所有视频总时长 ≥ 目标。未达标时显示 `32m/2h` |
| **剪辑** | 素材达标 → 进入「剪辑中」（主体是人，系统只看不干预） |
| **字幕** | `剪辑/*_corrected.srt` 存在 |
| **导出** | `剪辑/` 下出现 ≥目标时长的单文件 |
| **拼接** | **先校验片头片尾**，再判 `成片/` 下视频数 ≈ 集数 |
| **命名** | `成片/` 文件名能与 `标题.md` 每条标题匹配 |
| **台账** | 该合集是否已写进某份台账（看登记，**不看 Excel 文件数**） |

> 上传暂缓，不在判定范围。

### 4.1 命令与人的动作

系统不阻塞、不等待。命令只在需要时被调用，前提由状态自然满足：

| 谁动手 | 命令 | 前提 |
|---|---|---|
| 人 | 剪映里创作剪辑 | 素材达标 |
| 人 | 剪映里点识别字幕 | 剪辑完成 |
| agent | `vedio correct` → `apply-srt` | 剪映导出了 `.txt` + `.srt` |
| 人 | 导入 `_corrected.srt` + **审查** | `_corrected.srt` 存在 |
| agent | `vedio export` | 人审完（**动作即信号，不另记**） |
| agent | `vedio splice` | 导出完成 |
| agent | `vedio rename` / `vedio ledger` | 拼接完成 |

### 4.2 夜间无人值守

因为不阻塞，夜间流程就是一条顺序命令：

```bash
vedio run --game 我的世界 --batch 2026-06 --collections 合集三,合集四 \
          --steps correct,apply-srt,export,splice,rename,ledger
```

- 同一合集内按 `steps` 顺序
- 一个合集失败 → 记事件、跳过、继续下一个，**不整体中断**
- 第二天 `vedio status` 一眼看出哪些失败、为什么

## 5. 不能动的规则（行为冻结）

改了会破坏已交付的批次，或与对接方约定不符：

| # | 规则 |
|---|---|
| 1 | **成片命名**：`{前缀} {发布合集名} 第{中文数字}集 {标题}.mp4`，各段之间**一个空格** |
| 2 | **网盘路径**：`/{月}/{主播}/{游戏栏目}/{发布合集名}/{文件名}` |
| 3 | **台账列序**：A 合集名 / B 精彩看点 / C 时长 / D 合集时长 / E 片头时长 / F 减片头 / G 主播 / H 类别 / I 集数 / J 年份 / K 内容介绍 / L 关键字 |
| 4 | **溢出文件命名**：`{合集号}-0.mkv` |
| 5 | **字幕 patch 格式**：`行号:纠正后内容` |
| 6 | **`_corrected.srt` 编码**：UTF-8 **无 BOM** + CRLF（对齐剪映自己导出的格式） |
| 7 | **合集目录名**：`合集一`~`合集九十九`（中文数字，不接受阿拉伯数字） |

## 6. 分期

| 期 | 交付 | 可用性 |
|---|---|---|
| **V1** | `context` + `init`/`splice`/`rename`/`ledger`/`status` | 半自动：目录约定生效，台账自动生成 |
| **V2** | `asr`/`export` 剪映自动化 | 夜间无人值守成立 |
| **V3** | 一批多合集排队 + 失败重试 | 端到端（到台账为止） |
| **暂缓** | 网盘自动上传 | 仍手工。百度网盘 MCP 已有 `upload_file`，只是不排期 |
