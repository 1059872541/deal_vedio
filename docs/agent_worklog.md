## 2026-06-07 质量度量与数据持久化

### 需求

做完性能指标后发现两个问题：
1. 指标每次输出同样内容，无法量化纠正质量，无法用于提示词优化
2. 数据没有持久化，不利于趋势分析和可视化

### 方案讨论

**问题 1：纠正质量量化**
- 没有 ground truth 就无法精确衡量，但可以做修正量统计
- 方案 A（P0）：解析 correct_subtitle 输出格式 `行号:纠正内容`，按同音字/术语/脏话分类计数
- 方案 B（P1）：建 20~30 条标注样本的回归测试集

**问题 2：数据持久化**
- 每次运行追加一条 JSONL 到 `logs/performance.jsonl`
- 包含耗时、tokens、缓存命中率、成本

### 状态

- [ ] 性能数据持久化 — 待编码
- [ ] 修正量统计 — 待设计
- [ ] 回归测试集 — 待建
