# 日志

> 出问题先看日志，不要猜。

## 日志在哪（重要）

`{批次}/log/` 下有四类文件，**别只看 `events.jsonl`**：

| 文件 | 内容 | 用途 |
|---|---|---|
| `run-{动词}-{时间}.log` | **一次命令调用的全部输出**（控制台看到什么它就有什么，含崩溃栈） | 想知道"刚才那次到底发生了什么"，看这个 |
| `events.jsonl` | 一行一个 JSON 的结构化事件 | 用来看"做了什么、花了多久、失败码"，`status` 读它 |
| `{日期}.log` | 同上的中文明文本，追加 | 人快速翻 |
| `agent-subtitle-{合集}-{时间}.log` | **agent 完整过程**：解析出的主题、知识库命中、模型流式回复正文、token 消耗 | 字幕纠错出问题时唯一能看的东西 |
| `agent-{run_id}.jsonl` | 同一过程的**结构化**版本（一行一个事件，`event` 是节点名） | 想按字段筛（比如只看 error）时用 |
| `export-{合集}-{时间}.log` | 剪映控制器找控件、等面板、等文件稳定的全过程 | 导出失败时唯一能看的东西 |

**日志在批次目录里，不在代码仓库里。** 曾经有两个空目录会把人带歪：
`deal_vedio/logs`（四月遗留）和 `src/logs`（旧 logger 的默认 `log_dir`）。
两个都删了，并写进 `.gitignore`；旧 logger 也不再在构造时建目录。
以后再看到它们出现，说明有代码绕过了 `vedio` 入口 —— 那是 bug。

**为什么要单独存**：旧 agent（`deal_video_agent/agent/logger.py`）原来只配了
`structlog.PrintLoggerFactory()`，输出只到控制台；它的 `save_to_json()`
从来没被调用过，`_log_events` 也一直是空的。模型还是**流式逐字 print** 的，
连 structlog 都不经过。现在两层都补上了：
`EventLog.capture()` 在阶段层把 stdout/stderr 整段 tee 到文件（连模型正文一起）；
旧 logger 把结构化事件写成 `agent-{run_id}.jsonl`。
注意 `nodes.py` 每次运行都会 `reset_logger()`，所以必须用
`set_default_log_dir()` 设进程级默认目录 —— 光传参会被冲掉。

**每次跑完，CLI 会自己打印日志目录**（`日志：…`），不用猜。

用户问「为什么改了这一句」「为什么这么慢」时，**先 `vedio logs` 找证据，不要猜**。
