```

         「做 我的世界 2026-06 的合集三到合集七，今晚跑」
```

## 三、具体验收动作（我跑，你看着核对）

### 3.1 建一个批次

```bash
python -m vedio init --game 我的世界 --batch 2026-07 --collections 3
```

期望：在 `D:\VedioRecords\工作区\我的世界-2026-07\` 下建出

```
game.yaml
素材库/  片头/  片尾/  术语库/  log/
合集/合集一/{素材,剪辑,成片}
合集/合集二/{素材,剪辑,成片}
合集/合集三/{素材,剪辑,成片}
```

并且 `game.yaml` 里已经填好默认值（2h / 6 分钟 / 20 集 / 1080P·30fps）。

### 3.2 看进度

```bash
python -m vedio status --game 我的世界 --batch 2026-07
```

期望输出类似：

```
我的世界-2026-07  3 个合集
  合集一   素材      待开始
  合集二   素材      待开始
  合集三   素材      待开始
```

### 3.3 端到端跑一段真东西

把一段测试视频放进 `合集一/剪辑/`，配好 `game.yaml` 的片头尾（用你放在 `工作区` 的 `2026-06-MC-开头-合集-1-3.mp4` 和 `2026-06-MC-结尾.mp4`），然后：

```bash
python -m vedio run --game 我的世界 --batch 2026-07 --collections 合集一 --steps splice,rename,ledger
```

期望：

1. `合集一/成片/` 出现 N 个文件，命名是
   `波波之我的世界 收集强力变身-上篇 第一集 林中小屋初探.mp4`
2. `我的世界-2026-07/台账.xlsx` 出现，列头是
   `合集名 | 精彩看点 | 时长（秒） | 合集时长（秒） | 片头时长（秒） | 减完片头合集时长（秒） | 主播 | 类别 | 集数 | 出品年份 | 内容介绍 | 关键字`
3. 台账里每个合集一行的 A 列 = `波波之我的世界 收集强力变身-上篇`，B 列逐集 = `第一集 林中小屋初探`…，C 列 = ffprobe 实测秒数
4. 再跑一次 `run`：**不重复劳动**，因为它看到 `stage` 已完成

### 3.4 想验证"唯一真相"是否成立

```bash
python -m vedio paths --game 我的世界 --batch 2026-07 --collection 合集一
```

期望打印出 12 个路径（素材/剪辑/成片/标题/片头/片尾/台账/日志…），**且全部真实存在**。这一条过了，说明"路径推导只在 context 一处"这个设计站得住。

## 四、本轮明确不做

| 不做 | 原因 |
|---|---|
| 剪映 GUI 自动化（识别/导入/导出） | 需要剪映在前台，只能在你的机器上验 |
| 网盘上传 | **暂缓**——你已明确不纳入当前自动化，仍手工上传 |
| 后台队列 | V2，但没有它也能"手动依次跑 step" |
| Web 界面 | DSH 对话就是界面 |
| 删除旧脚本 | 等新版跑通再删，旧代码先原样留着 |

## 五、怎么判断这一轮成功

**成功 = 你看到这四件事，且都符合预期：**

1. 一条命令建出规范的批次目录，不用手改任何代码
2. 一条命令看到每个合集走到哪
3. 一段视频 + 片头尾 → 切分拼接到重命名到台账，全链路无人干预
4. 重跑不重复劳动

**失败 = 下面任一发生：**

- 路径还得靠人告诉它
- `game.yaml` 改了但行为没变（说明没真正读它）
- 台账列错位或时长对不上
- 重跑把已完成的东西又做了一遍

## 六、第一刀落在哪

`vedio/context.py` —— 它只干一件事：`(游戏, 批次, 合集) → 全部路径 + 配置`。

**为什么先切这里**：它是整个架构的地基。地基错了，后面全歪；地基对了，每个 stage 都只是"拿 ctx 干活"。

写完之后第一件事不是继续写，而是跑 `paths` 打出 12 个路径给你对。**对不上就改，对上再往上盖。**
