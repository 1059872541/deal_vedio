# 批次、目录与流水线

> 建批次、目录约定、进度表、加合集、篇名。命令的**行为**由代码决定，这里说明它是什么。

## 建新批次

1. 先看工作区里已有什么批次：

```powershell
Get-ChildItem "<workspace.root>" -Directory
```

2. 确认是新建还是继续。新建才往下走。

3. 读规则，把默认值摊给用户看：

```
依据 conf/默认规则.yaml + conf/游戏规则/{游戏}.yaml

  素材   2.5 小时 / 合集
  集数   20 集 / 合集
  正文   7:30 / 集
  导出   1080P / 30fps / H.264 / mp4
  命名   {主播}之{游戏} {副标题}，中间一个空格

要改哪一项吗？（直接回车 = 全部按上面）
```

4. 再问两项本批次信息：**主播是谁**、**建几个合集**。

5. 执行建批次，然后告诉用户目录建好了、下一步把录屏放进 `合集\合集X\素材\`。

**建完之后 `game.yaml` 是完整快照**，之后所有环节只读它，不再看 `conf/`。

## 目录约定

```
<workspace.root>\
└── {游戏}-{批次}\
    ├── game.yaml          ← 本批次完整配置（建完就定稿）
    ├── 进度.md            ← 每个合集走到哪一步（人可手改；见 §4.2）
    ├── 素材库\            ← 剪辑原料（打招呼语音、混剪片段）。程序不读
    ├── 片头\  片尾\       ← 已合成的成品，拼接时直接用
    ├── 术语库\
    ├── log\
    ├── 标题.md            ← 公共前缀 + 每合集一节（副标题 + 20 条标题）。重命名和台账都读它
    ├── 合集清单.yaml       ← 草稿名、片头片尾映射。程序写，人只核对
    ├── 台账.xlsx
    └── 合集\合集X\
        ├── 素材\          ← OBS 原始录屏
        ├── 剪辑\          ← 草稿、2h 导出、.srt、corrected.txt
        └── 成片\          ← 20 个成片
```

**取路径不要自己拼**：用 `vedio paths --game X --batch Y --collection Z --json`。

### 4.1 目录里放着但不该参与流水线的

合集列表是**扫目录**得来的（`game.yaml` 的 `collections: N` 只在建批次时用来建目录）。
所以往 `合集/` 里随便放一个 `合集三/`（例如放测试素材），它立刻会被当成正式合集：
`status` 算它一集没录，批量跑 `subtitle` / `run` 不加 `--collections` 也会动到它。

**要保留但不想让它参与，就在 `game.yaml` 里登记：**

```yaml
ignore_collections:
  - 合集三
```

被忽略的目录**原样保留**（不删、不改），只是不统计、不处理。
`status` 会显式打一行「忽略：合集三」，不会让它悄悄消失。

### 4.2 进度表 `进度.md`

每个批次一张，`init` 时生成（全 `·`），记每个合集走到哪一步。
**它是记录，不是证据** —— 判断一律以文件为准，`status` 才是体检。

```markdown
| 合集 | 剪辑 | 字幕 | 篇名 | 导出 | 拼接 | 命名 | 台账 |
|---|---|---|---|---|---|---|---|
| 合集一 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | 台账-01 |
```

三条规矩：

1. **程序只打 ✓，永不擦回 `·`** —— 退回状态只有人能做
2. **人可以直接改** —— 表格外面的备注、自己加的列都原样保留
3. **表被改乱了不怕** —— 程序先备份成 `.bak` 再重建

**为什么不做文件校验**：每个环节都有人兜底（录、剪、导字幕审查、交付前过目）。
准确性来自甲方压力和人的记忆；程序再验一遍也只验得出"文件在不在"，
验不出"这件事做没做过"，还要付 ffprobe 的代价。

### 4.3 给已有批次加合集

批次不是一次建全的。先做 1–3 个交付了，过几天继续做 4、5 个：

```powershell
vedio init --game 我的世界 --batch 2026-12 --add 合集四,合集五
```

- 只补缺的子目录（`素材/` `剪辑/` `成片/`），**已有的一个不动**
- 进度表追加行（已有行原样保留）
- `game.yaml` 的 `collections` 更新到最大序号（只替换那一行数字，不碰注释）
- 幂等：都加过了就如实报"已存在"

### 4.4 篇名是硬门槛（导出之前必须定）

流程里「篇名」排在「字幕」之后、「导出」之前：

```
素材 → 剪辑 → 字幕纠正/标题生成 → 篇名 → 导出 → 拼接 → 命名 → 台账
```

**为什么不能更晚**：台账必须有篇名（它是交付凭证），成片文件名也要用。
等导完、拼完、要写台账了才发现没有，整轮白跑。

- `vedio export` 会拒绝没有篇名的合集（`error=title_missing`）
- `vedio ledger` 同样拒绝，不会写一张缺列的表
- 进度表 `进度.md` 里对应一列 `篇名`

**怎么定**：先让模型提一个，再由人拍板（篇名是门面）：

```powershell
vedio series --game 我的世界 --batch 2026-12 --suggest "合集一,合集二"
# → 我给这一组起了个篇名：罗盘寻迹下界行
#   这几个合集算同一篇（上篇/下篇）。

vedio series --game 我的世界 --batch 2026-12 --groups "合集一,合集二=罗盘寻迹下界行"
```

**同一篇的合集写在一起**（逗号分隔），程序自动分「-上篇 / -下篇」。
