# 字幕规模与 token 参考

> 用来回答一个问题：**手里这段素材，跑纠错要吃掉多少 token、多少时间？**
> 数据来自两次真实运行（`deepseek-flash`，走生产同一条链路 `run_subtitle_agent`）。
> 实测只有两个点，其余是按拟合关系推算，表里标了「实测 / 推算」。

---

## 一、两个实测样本

| 项目 | 样本 A | 样本 B |
|---|---|---|
| 素材时长 | 21 分 32 秒 | 2 小时 |
| 剪映导出的 `.txt` | 7,503 B | 31,921 B |
| 加行号后的 `_ordered.txt` | 8,711 B | **38,574 B** |
| 字幕行数（块数） | 329 行 | **1,552 行** |
| 平均每行字数 | 6.8 字 | 6.5 字 |
| prompt tokens | 5,378 | **14,035** |
| completion tokens | 12,381 | **34,482** |
| completion ÷ prompt | 2.30 | 2.46 |
| `finish_reason` | `stop` | `stop` |
| 纠错耗时 | 106 秒 | 231 秒 |
| 标题生成 | 命中缓存，没调 API | prompt 11,310 + completion 3,846 |

两档的 `completion ÷ prompt` 都在 **2.3~2.5**，说明这个比例是稳定的，
可以放心用它做预估。

## 二、换算关系

从上面两个点拟合出来的四条式子（中文游戏解说、口语密度正常的情况）：

```
行数            ≈ 时长(小时) × 850 行          （实测区间 780 ~ 920）
加行号后大小    ≈ 原始 txt × 1.2               （实测 1.16 ~ 1.21，行数越多倍数越大）
prompt token    ≈ 2,850 + 加行号后字节 ÷ 3.45  （固定 2,850 = 知识库 + 提示词模板）
completion      ≈ 2.4 × prompt
总 token        ≈ 1.31 × (prompt + completion) （多出来的 31% 是标题生成）
耗时            ≈ completion ÷ 150 秒          （实测 150~167 tok/s）
```

那个 **2,850 的固定部分**是知识库文件加模板撑起来的。样本用的是
`conf/知识库/我的世界/我的世界愚者整合包.md`（9,708 B）。
**换游戏、或知识库明显更大/更小，这一项要按比例改** —— 它大约等于
`知识库字节 ÷ 3.4 + 500`。

## 三、查表

「总 token」= 纠错 + 标题生成。2 小时那个样本两种调用都跑过：
纠错 48,517（prompt 14,035 + completion 34,482）+ 标题 15,156 = **63,673**，
所以总 / 纠错 = 1.31。

| 时长 | 行数 | 原始 txt | 加行号后 | prompt | completion | 纠错 token | 总 token | 纠错耗时 | 依据 |
|---|---|---|---|---|---|---|---|---|---|
| 30 分钟 | ~425 | ~8,850 B | ~10,600 B | 5,900 | 14,200 | ~20,200 | ~26,400 | ~1.5 分 | 推算 |
| **21 分钟** | **329** | **7,503 B** | **8,711 B** | **5,378** | **12,381** | **17,759** | —¹ | **106 秒** | **实测 A** |
| 1 小时 | ~850 | ~17,700 B | ~21,300 B | 9,000 | 21,600 | ~30,600 | ~40,100 | ~2.4 分 | 推算 |
| 1.5 小时 | ~1,275 | ~26,600 B | ~31,900 B | 12,100 | 29,000 | ~41,100 | ~53,900 | ~3.2 分 | 推算 |
| **2 小时** | **1,552** | **31,921 B** | **38,574 B** | **14,035** | **34,482** | **48,517** | **63,673** | **231 秒** | **实测 B** |
| 3 小时 | ~2,550 | ~53,100 B | ~63,800 B | 21,300 | 51,200 | ~72,500 | ~95,000 | ~5.7 分 | 推算 |

¹ 样本 A 的标题命中了缓存、没调 API，所以只有纠错的 17,759；实际首次跑要再加约 5,000。

**推算行和实测行差多少**：拿 2 小时的字节数套公式 → prompt 15,169 / completion 36,405，
实测是 14,035 / 34,482，**prompt 偏高 8%、completion 偏高 6%**。
推算只用来估量级，不要当准数。

## 四、给已有素材做估算（30 秒）

**① 直接查表**：知道时长就够，按上一节的表对号入座。

**② 手里有文件时，先数行和字节**：

```powershell
$f = "D:\VedioRecords\工作区\我的世界-2026-12\合集\合集三\剪辑\2026-06-MC-合集3.txt"
"行数: " + (Get-Content $f).Count
"字节: " + (Get-Item $f).Length
```

**③ 套公式**：

```
加行号后 ≈ 原始字节 × 1.2
prompt   ≈ 2850 + 加行号后 ÷ 3.45
completion ≈ 2.4 × prompt
耗时(秒) ≈ completion ÷ 150
```

例：`31,921 B` → 加行号 38,305 → prompt 13,952 → completion 33,485
（实测 14,035 / 34,482，误差 1~3%）

## 五、`max_tokens` 怎么定

| 素材规模 | 建议 `max_tokens` |
|---|---|
| ≤ 1 小时 | 32,768 |
| 1 ~ 2 小时 | 65,536 |
| 2 ~ 5 小时 | **98,304**（当前配置） |
| > 5 小时 | 建议先分块，别硬提额度 |

三条原则：

1. **它是上限，不是预留。** 模型说完就停，按实际用量计费 —— 给大不浪费钱。
2. **给少了会静默失败。** 推理吃光额度时正文为空、`finish_reason=length`，
   表现是"跑了几分钟，字幕一处没改"。
3. **代码会在开跑前预检**：按 prompt 体量估额度，不够就打 `[WARNING]`。
   实测它会把 `32768` 判为不够（而 2 小时真实需要 34,482），判断是准的。

配置在 `conf/agent.yaml`。

## 六、关于成本

这里只给 token 量，**不给单价** —— 单价随模型和官方调价变，本仓库不维护价目表。
`subtitle_agent.py` 里的 `MODEL_PRICES` 是空的，所以性能报告只报 token 数、不算钱。

要看钱：拿上表的 token 数乘当前官方单价即可。
