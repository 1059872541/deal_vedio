# 状态怎么判、边界怎么处理

> `status` 的判定口径，以及两类边界：素材超额、片头片尾缺失。

## 状态怎么判（全部看文件，不看数据库）

| 状态 | 判定                                                                            |
| ---- | ------------------------------------------------------------------------------- |
| 素材 | `素材/` 下视频总时长 ≥ `duration.material_per_collection`                       |
| 剪辑 | 素材达标即进入「剪辑中」，主体是人                                              |
| 字幕 | `剪辑/*_corrected.srt` 存在                                                     |
| 导出 | `剪辑/` 下有 ≥ 素材目标时长的单文件                                             |
| 拼接 | **先校验片头片尾**（见 §5.2），再判 `成片/` 下视频数 ≈ `duration.episode_count` |
| 命名 | `成片/` 文件名能与 `标题.md` 的标题匹配                                         |
| 台账 | 该合集是否已写进某份台账                                                        |

### 5.1 素材超出目标时 —— 决策在你，脚本只执行

脚本只提供两个**原子能力**，它不判断"该不该匀"：

**① 查事实（只读）**

```powershell
.venv\Scripts\python src\util\balance.py check --game <游戏> --batch <批次>
```

输出每个合集的素材总时长、目标、超出多少。**没有任何建议，也不含"有没有下一个合集"的判断。**

**② 切走一个合集的多余部分**

```powershell
.venv\Scripts\python src\util\balance.py move --game <游戏> --batch <批次> --from 合集一 --to 合集二
# 加 --apply 才真正执行
```

它只做"从 A 切到 B"这一件事。`--to` 指向的合集不存在就直接报错退出 —— **不猜、不支招**。

**你要做的判断（脚本不管）：**

1. `check` 后看哪些合集 `超出 > 0`
2. 自己判断它有没有下一个合集可以接收：
   - **有** → 用一句话问用户：「合集一超了 6 分钟，匀到合集二？关键帧处切开，不重编码，画质无损。」
   - **没有** → 如实说：「这批只建了 1 个合集，没地方匀。要么多建一个合集，要么接受这集超长。」
3. 用户同意 → `move --from <源> --to <目标> --apply`
4. 再 `check` 一次；如果接收方反而超限了，**由你循环再做 2–3**（级联是你的循环，不是脚本的）

> 切割用 `-c copy`，切点落在关键帧上，实际溢出时长有几秒误差 —— 正常。
> `check` 的"是否超限"用「目标 + `duration.segment_tolerance`」判定，刚好达标不会误报。

### 5.2 拼接前必须校验片头片尾

**片头片尾不要求建批次时就有。** 通常正片素材先录，片头片尾最后才录/合成。

所以只在**开始拼接之前**校验，三项都要满足：

1. `合集清单.yaml` 的 `templates.intro_mapping` 能解析出本合集的片头（按合集名查，查不到用 `default`）
2. `templates.outro` 有值
3. 这两个路径指向的文件**真实存在**

**任一项不满足 → 立即停下，不要开始拼接，也不要拿别的文件代替。** 这样告诉用户：

> 合集一还缺片头（`合集清单.yaml` 里 `templates.intro_mapping` 是空的）。
> 拼接是「片头 + 正片 + 片尾」，缺了拼不出来。
> 录好放到 `片头/` 目录，我把它登记进 `合集清单.yaml`，然后再继续。

三项齐全后才可以继续拼接。
