## 1. 这条流水线做什么

```
录屏 → 剪映剪辑 → 字幕纠正 → 导出 → 切分拼接 → 重命名 → 台账
```

**人只做两件半事**：录制、剪辑、审字幕。其余环节由程序接管。

**代码和数据分开**：

| | 在哪 | 进 git |
|---|---|---|
| 代码 + 规则 | 本仓库（`conf/`、`src/`） | ✅ |
| 视频数据 | `conf/本机.yaml` 指定的工作区 | ❌ |

## 3. 你要交给程序的 4 样东西

程序拿不到的东西只有这些，缺一样就得停下：

| # | 交出什么 | 放到哪 | 规格 |
|---|---|---|---|
| 1 | **素材** | `合集/合集X/素材/` | OBS 原片，双音轨 |
| 2 | **字幕两件套** | `合集/合集X/剪辑/` | **一个 `.txt`（无行号）+ 一个 `.srt`**。每个目录只能有一个，文件名随意 |
| 3 | **草稿名** | 说一次即可 | 剪映里那个草稿叫什么。程序会记进 `合集清单.yaml`，之后不再问 |
| 4 | **片头片尾** | `片头/`、`片尾/` | 已合成的成品 mp4。**拼接前才校验**，建批次时不用有 |

其余全部由程序自己查：目录、时长、集数、命名规则、导出参数。

## 4. 时间账

| 项 | 每合集耗时 | 构成 |
|---|---|---|
| **人在操作** | **≈12 min** | 查首尾 1 + 音轨 5 + 审字幕 5 + 查元素 1 |
| 人在等待 | ≈15–30 min | 字幕识别（可离开，但要回来） |
| **机器在跑** | **≈50 min** | 导出 45 + 切分拼接 ~5 |
| 录制 | 2–3 h | 与其它环节串行，压不掉 |

**目标**：墙钟时间 ≈ 导出时间，可以过夜。

## 5. 批处理：两个正交维度

「全流程」和「从中间开始」不是两套流程，是同一套能力的两种用法。

| 维度 | 取值 |
|---|---|
| **流程位置** | 从建批次走到底，或从任意环节切入 |
| **合集范围** | 一个合集，或本批次任意多个 |

```bash
# 只匀素材，三个合集一起
vedio balance --game 我的世界 --batch 2026-12 --collections 合集一,合集二,合集三 --apply

# 只做后半段，三个合集一起
vedio run --game 我的世界 --batch 2026-12 --collections 合集一,合集二,合集三 \
          --steps export,splice,rename,ledger
```

**关键：前提不是"上一步刚跑过"，而是"文件状态满足"。** 所以从任意环节开始都成立。

| 环节 | 前提 |
|---|---|
| `export` | 草稿已登记 + 人已审完字幕 |
| `splice` | `剪辑/` 有 ≥目标时长的长片 + 片头片尾齐 |
| `rename` | `成片/` 有视频 + `标题.md` 里该合集有副标题 |
| `ledger` | 参与本次的合集都已完成拼接与命名 |

一个合集失败**不拖累其它**，就是这个设计的直接结果。
